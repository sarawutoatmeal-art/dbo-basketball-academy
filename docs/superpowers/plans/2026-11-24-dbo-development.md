# แผนพัฒนา DBO Basketball Academy
วันที่ 24 พฤศจิกายน 2569 · อ้างอิงจากโค้ดและแอป local ปัจจุบัน

**เป้าหมาย** ให้โค้ชเช็กชื่อข้างสนามได้เร็ว ผู้ปกครองติดตามสิทธิ์และพัฒนาการได้ และทีมตรวจสอบข้อมูลได้ก่อนเปิดใช้จริง

**โครงสร้าง** ใช้เว็บและระบบบันทึกที่มีอยู่ต่อ พัฒนาเป็นงานย่อยที่ทดสอบแยกกันได้ หน้าหลักยังเป็นศูนย์รวมคลาสวันนี้ รอบถัดไป และยอดเข้าเรียนสี่สัปดาห์

**สแต็ก** HTML, CSS, JavaScript, Node.js และระบบซิงค์ที่มีอยู่ในโปรเจกต์

## 1. ทำให้วันที่และยอดเช็กชื่อตรงกัน

- [x] ตรวจเส้นทางแจ้งเข้าเรียนและลาใน `js/modules/parent.js` ให้วันที่ที่แสดงในฟอร์มตรงกับวันที่บันทึก ปัจจุบันฟอร์มอ่านวันที่ที่เลือก แต่เรียกฟังก์ชันที่บันทึกลงวันที่วันนี้ หากเปิดให้เลือกวันอื่น ให้ส่งวันที่เข้าไปถึงจุดบันทึกและใช้วันเดียวกันในข้อความยืนยัน
- [x] ใช้ข้อมูลเช็กชื่อชุดเดียวกันในประวัติผู้ปกครองและยอดโค้ช รักษาการอ่านข้อมูลเก่าที่มีอยู่ และแยก “ยังไม่มีบันทึก” ออกจาก “ยอดเป็นศูนย์”
- [ ] ตรวจด้วยข้อมูลทดสอบสามกรณี ได้แก่ วันนี้ วันถัดไป และช่วงข้ามเที่ยงคืนเวลาไทย เทียบวันที่ในบันทึก ประวัติ และหน้ารวมยอด

## 2. โหมดข้างสนามสำหรับโค้ช

- [x] เพิ่มทางลัด **เช็กชื่อคลาสวันนี้** จากหน้าหลัก เปิดฟอร์มรอบเดิมที่ `openNewTeachingRecordModal()` ใน `js/modules/attendance.js` ให้เห็นวันที่และประเภทคอร์สก่อนกดบันทึก
- [x] ปรับรายการใน `populateRecordChecklist()` ให้แตะ **มา / ลา / ยังไม่ระบุ** ได้จากแถวเดียว ใช้สถานะในข้อมูลเป็นตัวอ้างอิงเดียวกันระหว่างแสดงผลและบันทึก แทนการอ่านคลาสสีของปุ่ม
- [x] ใช้เส้นทางบันทึกเดิมของ `saveTeachingRecordFromModal()` ตรวจว่าแตะบันทึกซ้ำไม่ตัดสิทธิ์ซ้ำ แก้ไขรายการแล้วคืนสิทธิ์ถูกคอร์ส และกรณีโควต้ารวมพี่น้องยังตรงกัน
- [ ] ทดสอบด้วยบัญชีโค้ชและผู้ช่วยโค้ช เปิดรอบ เลือกสถานะ ค้นหานักเรียน บันทึก และกลับมาแก้ไขที่จอ 320 และ 390 พิกเซล

## 3. สรุปหลังซ้อมและการ์ดนักกีฬา

- [x] เพิ่มปุ่ม **สรุปหลังซ้อม** ในบันทึกการสอน ใช้วันที่ หัวข้อ และจำนวนมา/ลาจากรายการจริง พร้อมทางลัดคัดลอกข้อความ ทดสอบว่าเนื้อหาที่คัดลอกตรงกับรอบที่เลือก
- [x] จัดหน้า **ข้อมูลนักเรียน** ใน `renderParentView()` ให้เห็นชื่อ คอร์ส สิทธิ์ การเข้าเรียนล่าสุด และคำแนะนำของโค้ชตามลำดับ ใช้การวัดสมรรถภาพและหมายเหตุที่มีอยู่ก่อนเพิ่มช่องใหม่
- [x] แสดงแนวโน้มรายคนเมื่อมีอย่างน้อยสองผลวัดที่เทียบกันได้และมีวันที่กำกับ กรณีมีผลเดียวให้แสดงค่าล่าสุด ทดสอบสลับนักเรียนในบัญชีพี่น้องว่าข้อมูลทุกส่วนเปลี่ยนไปพร้อมกัน

## 4. แผนอัปหน้าตา DBO

ให้หน้าหลักและหน้าคลาสมีบรรยากาศเหมือนแอปทีมบาส ใช้สกอร์บอร์ด เส้นสนาม และภาพจริงของ DBO เป็นจุดเด่น ส่วนหน้าเช็กชื่อ สมัครเรียน และชำระเงินจัดให้สแกนข้อมูลได้เร็ว

### 4.1 ระบบภาพและขนาดร่วมกัน

- [ ] ใช้ม่วงเข้ม `#241044` สำหรับหัวหน้าทีมและสกอร์บอร์ด ม่วง `#38196B` สำหรับปุ่มหลัก ทอง `#DEB95B` สำหรับเส้นเน้นและสถานะที่เลือก และขาวสำหรับฟอร์มกับการ์ด ใช้เขียว เหลือง แดง และจุดสีปฏิทินตามความหมายเดิม
- [ ] ใช้หัวข้อหลัก 24–32 px หัวข้อย่อย 18–22 px ข้อความอธิบาย 14 px ช่องกรอก 16 px และพื้นที่แตะของปุ่มหลักอย่างน้อย 44 px ไอคอนปุ่มทั่วไป 16 px และไอคอนเมนู 18 px
- [ ] รวมสไตล์ซ้ำของปุ่ม การ์ด แท็บ ตาราง และหน้าต่างย่อยใน `css/style.css` แก้ HTML และเทมเพลตที่ JavaScript สร้างให้ใช้รูปแบบเดียวกัน ยึดข้อความไทยสั้น ๆ และใช้ป้ายสถานะเมื่อมีข้อมูลให้ผู้ใช้อ่านจริง

### 4.3 รอบออกแบบและเกณฑ์ส่งมอบ

- [ ] รอบแรกปรับหน้าหลัก คลาสวันนี้ และยอดรายวันให้เห็นทิศทางกีฬา แล้วนำขนาดและรูปแบบเดียวกันไปใช้กับปฏิทินและแผงโค้ช
- [ ] รอบสองตรวจเส้นทางผู้ปกครอง ตั้งแต่เข้าสู่ระบบ ดูสิทธิ์ สมัครเรียน จนถึงต่อคอร์สและเห็นยอดชำระ
- [ ] เก็บภาพก่อน–หลังและตรวจหน้าแอปจริงที่ 320, 390, 768 และ 1440 px ใช้ชื่อยาว ข้อความสองบรรทัด ข้อมูลว่าง และยอดหลายหลักในการทดสอบ
- [ ] ก่อนส่งมอบ ตรวจการแตะ การใช้คีย์บอร์ด การลดการเคลื่อนไหว และการแสดงผลแบบติดตั้งบนโทรศัพท์จริง โดยเฉพาะแถบหัวและเมนูด้านล่าง

## 5. เตรียมเปิดใช้กับข้อมูลจริง

- [ ] ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ก่อนเปิดใช้จริง การเข้าสู่ระบบทีมงานปัจจุบันตรวจเบอร์ในเบราว์เซอร์ และในตัวจัดการ `api/sync.js` ที่ตรวจ ยังไม่เห็นการตรวจสิทธิ์ก่อนคืนหรือรับสถานะ ทีมควรให้เซิร์ฟเวอร์ยืนยันบัญชีและคืนเฉพาะข้อมูลที่บทบาทนั้นมีสิทธิ์เข้าถึง
- [ ] แยกข้อมูลทดสอบออกจากข้อมูลจริง รวมถึงข้อมูลที่ฝังมากับไฟล์หน้าเว็บ ทดสอบว่าผู้ปกครองอ่านได้เฉพาะนักเรียนที่ผูกบัญชี และผู้ช่วยโค้ชทำได้ตามสิทธิ์
- [ ] ก่อนเผยแพร่ ให้ทดสอบเช็กชื่อจากสองเครื่องพร้อมกัน ตรวจยอดหลังตัดสิทธิ์ สำรองข้อมูล และลองกู้คืนจากชุดสำรองในสภาพแวดล้อมทดสอบ

**ลำดับส่งมอบ** เริ่มแก้วันที่และการบันทึก จากนั้นทำโหมดข้างสนามและสรุปหลังซ้อม แล้วต่อยอดการ์ดนักกีฬาและภาพของทีม งานตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทำคู่กันได้ และต้องผ่านก่อนใช้ข้อมูลจริง

## ผลตรวจบนเครื่อง วันที่ 25 พฤศจิกายน 2569

- หน้าหลัก คลาสวันนี้ ปฏิทิน สมัครเรียน และแผงโค้ชเปิดได้ผ่านเมนูจริงที่ 320, 390, 768 และ 1440 พิกเซล เลย์เอาต์หลักและเนื้อหาไม่ล้นแนวนอน

- ใช้ `npm test` ตรวจวันที่กรุงเทพฯ การจับคู่รอบกับคำตอบผู้ปกครอง บันทึกซ้ำ ย้ายคอร์ส คืนสิทธิ์แยกรายคน สลับพี่น้อง คัดลอกสรุป ผลวัดย้อนหลัง และเดือน 4–6 แถว
- โหมดทดสอบใช้ข้อมูลในเบราว์เซอร์และซิงค์ระหว่างแท็บบนต้นทางเดียวกัน ตรวจว่าไม่เรียก API ซิงค์หรือเปิด MQTT และ Node.js บนพอร์ต 3000 ตอบ 404 สำหรับการอ่านและเขียนสถานะทาง `/api/sync`

### งานที่ยังต้องผ่านก่อนเปิดใช้จริง

- ผูกระบบยืนยันตัวตนฝั่งเซิร์ฟเวอร์และตรวจสิทธิ์ทีมงาน ผู้ช่วยโค้ช และผู้ปกครองทุกคำขอ ย้ายข้อมูลนักเรียนออกจากไฟล์สาธารณะ และใช้แหล่งเก็บข้อมูลที่รองรับการบันทึกรอบเดียวกันพร้อมกัน
- ทดสอบบนสภาพแวดล้อมแยกด้วยบัญชีโค้ช ผู้ช่วย และผู้ปกครองสองครอบครัว ให้เครื่องสองเครื่องบันทึกรอบเดียวกันและยืนยันว่าตัดสิทธิ์ครั้งเดียว พร้อมทดสอบกู้คืนจากไฟล์สำรอง
- ทดสอบเส้นทางผู้ปกครองและต่อคอร์สบนเครื่องจริง รวมถึง PWA ที่ติดตั้งแล้ว โหมดลดการเคลื่อนไหว และตัวอย่างพิมพ์ A4
